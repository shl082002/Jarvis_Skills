# Ideate — force the bet into the open

PEPPER hat for customer eyes; stay in **DISCUSS** (`skills/two-modes/`).
Output is a chronicle plan or decision note — not a second brain, not
`~/.gstack` learnings.

## Forcing questions

Load `references/forcing-questions.md`. Ask the ones that bite **this**
product. Do not run a 40-question script.

Minimum set:

1. **Demand** — what behavior (not compliments) proves someone needs this?
2. **Status quo** — what painful workaround exists today? If “nothing,”
   why act?
3. **Wedge** — what is the narrowest first slice that would be missed if
   it vanished tomorrow?

## Procedure

1. Restate the idea in one sentence the principal can reject.
2. Hit demand → status quo → wedge. Push on mushy answers once, then record
   the gap instead of lecturing.
3. Name 2–4 decision points with a recommendation each.
4. Write or update a chronicle plan (`skills/chronicle/`). Memory only if
   they lock a ruling — a pointer, not the essay.
5. Stay in DISCUSS until their words switch modes.

## Never

Code, scaffolds, agent launches, `/office-hours` as a foreign brand,
auto-QA because the idea “sounds testable.”
